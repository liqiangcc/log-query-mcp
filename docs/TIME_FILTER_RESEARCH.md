# R-09 时间范围、日志时间戳与轮转排序预研

> 状态：核心 POC 已通过严格 CI  
> 实现：`src/time_filter.rs`

## 1. 目标

问题排查通常只知道大致发生时间。时间能力需要同时解决：

- 校验客户端的查询时间范围。
- 解析不同日志格式中的行时间戳。
- 让异常堆栈续行继承所属事件时间。
- 避免畸形事件时间错误继承上一条日志时间。
- 根据时间过滤候选结果。
- 对多个服务结果建立稳定、可解释的顺序。
- 结合轮转文件名和文件修改时间排序候选文件。

本阶段只验证时间解析和排序原语，尚未把它们接入真实 MCP 搜索编排器。

---

## 2. 查询时间范围

客户端时间参数使用 RFC 3339：

```text
start_time
end_time
```

时间区间采用：

```text
[start_time, end_time)
```

即：

- 开始时间包含在范围内。
- 结束时间不包含在范围内。
- 相邻时间窗口不会重复包含边界日志。
- 同时提供开始和结束时间时，开始时间必须早于结束时间。
- 可以只提供一个边界。
- 不合法 RFC 3339 字符串直接拒绝。

示例：

```text
[14:00:00, 15:00:00)
```

包含 `14:00:00`，不包含 `15:00:00`。

## 3. 日志行时间戳规则

每个日志来源可以配置一种 `TimestampRule`。

### 3.1 RFC 3339

```rust
TimestampRule::Rfc3339 {
    prefix_bytes: 64,
}
```

`prefix_bytes` 是允许检查的最大前缀字节数。解析器读取该范围内第一个空白字符之前的 token，因此同时支持：

```text
2026-06-19T14:20:03+09:00
2026-06-19T14:20:03.125+09:00
2026-06-19T05:20:03Z
```

### 3.2 自定义固定前缀

```rust
TimestampRule::Custom {
    prefix_bytes: 23,
    format: "%Y-%m-%d %H:%M:%S%.3f",
    default_offset_seconds: Some(9 * 3600),
}
```

适用于：

```text
2026-06-19 14:20:03.125 ERROR ...
```

当格式本身不包含时区时，由日志来源提供默认 UTC 偏移。

配置限制：

- 时间戳前缀最大 256 字节。
- 格式字符串最大 128 字符。
- 时区偏移必须在 chrono 支持范围内。
- 自定义前缀必须位于 UTF-8 字符边界。

## 4. 多行事件时间继承

异常堆栈通常只有第一行包含时间：

```text
2026-06-19T14:20:03+09:00 ERROR PaymentAuthException
    at payment::authorize(...)
Caused by: forbidden
```

`TimestampTracker` 的行为：

1. 成功解析事件行时，保存该时间。
2. 后续不带时间前缀的行继承上一事件时间。
3. 文件切换时调用 `reset()`，禁止跨文件继承。
4. 第一条可解析时间之前的行保持未知。

每条观察结果包含：

```text
timestamp
inherited
malformed
```

---

## 5. 畸形时间戳处理

不能把所有解析失败的行都当成异常堆栈续行。

例如：

```text
2026-99-99T99:99:99+09:00 ERROR malformed
```

它明显像一个新事件，但时间值不合法。如果继续继承上一条事件时间，会把该事件错误归入上一请求。

当前策略：

- 行首前四个字符为数字，随后为 `-` 或 `/`，但配置规则无法解析：标记 `malformed=true`。
- 清空上一事件时间。
- 该行时间为未知。
- 后续无时间堆栈行不再继承更早事件时间。

时间过滤将畸形时间和普通未知时间区分为：

```text
UnknownTimestamp
MalformedTimestamp
```

正式搜索编排器应保守保留匹配内容并返回空时间戳，而不是静默丢弃，以避免由于日志格式异常产生漏报。

---

## 6. 时间过滤决策

`TimeRange` 可以将日志结果分类为：

```text
InRange
OutOfRange
UnknownTimestamp
MalformedTimestamp
```

建议正式编排规则：

- `InRange`：正常返回。
- `OutOfRange`：过滤。
- `UnknownTimestamp`：保守返回，`timestamp=null`。
- `MalformedTimestamp`：保守返回，`timestamp=null`，服务端记录格式告警。

不能仅因为时间无法解析就隐藏匹配日志。

---

## 7. 轮转文件时间提示

日志来源可以配置轮转文件名时间规则：

```rust
RotationTimestampRule {
    prefix: "application-",
    suffix: ".log",
    format: "%Y-%m-%d",
    default_offset_seconds: 9 * 3600,
}
```

可以解析：

```text
application-2026-06-19.log
```

该时间仅作为候选文件排序提示，不代表文件内每一行的准确时间。

配置限制：

- 前缀和后缀各不超过 128 字符。
- 时间格式不超过 128 字符。
- 文件名不匹配规则时返回无时间提示。

## 8. 当前日志与轮转日志统一排序

候选文件可能同时包含：

```text
application-2026-06-18.log
application-2026-06-19.log
application.log
```

轮转文件使用文件名时间提示；当前文件通常没有提示，因此使用文件修改时间。

两种时间都转换到 UTC 后放入同一时间线比较，避免以下错误：

- 因为当前文件没有轮转时间提示，就总是把它放在最后。
- `newest_first` 时先扫描旧轮转日志。
- 不同时区的文件提示直接按字符串比较。

稳定排序规则：

```text
候选时间
→ source_index
→ relative_path
```

支持：

```text
oldest_first
newest_first
```

## 9. 跨服务结果排序

`TimedLogResult` 保存：

```text
timestamp
source_index
file_index
line_number
value
```

结果排序规则：

```text
可解析时间
→ source_index
→ file_index
→ line_number
```

无时间结果统一放在有时间结果之后，无论升序还是降序。

这保证：

- 有时间日志可以用于还原调用链。
- 无时间结果不会伪装成精确时间线。
- 相同时间戳下仍有稳定、可重复的顺序。

注意：不同服务器时钟可能存在偏差。跨服务排序只能反映日志记录的时间，不能保证真实因果顺序。

## 10. 已覆盖的自动化用例

- RFC 3339 带毫秒和不带小数秒。
- RFC 3339 `Z` 与固定偏移表示同一时刻。
- Java 风格本地时间加默认时区。
- 异常堆栈继承事件时间。
- 第一条时间之前的日志保持未知。
- 畸形事件时间清空继承状态。
- 开始包含、结束排除的时间范围。
- 拒绝反向、相等和格式错误的时间范围。
- 解析日期型轮转文件名。
- 跨服务结果升序和降序排序。
- 无时间结果始终位于可解析结果之后。
- 当前日志和轮转日志统一时间线排序。
- `newest_first` 优先当前较新日志。

## 11. 当前结论

R-09 核心时间原语结论为 **GO**。

已验证：

- 两类常用日志时间格式可配置解析。
- 多行异常可以继承所属事件时间。
- 畸形事件时间不会污染后续行。
- 时间区间语义明确。
- 当前日志和轮转日志能够统一排序。
- 跨服务结果具备稳定顺序。

正式接入 MCP 前仍需完成：

1. 将 `start_time` 和 `end_time` 的实际解析加入工具运行时校验。
2. 为每个日志来源加载时间戳和轮转规则。
3. 将时间跟踪集成到流式扫描器或多文件编排器。
4. 文件切换时重置 `TimestampTracker`。
5. 明确未知和畸形时间结果在 MCP 响应中的提示字段。
6. 用文件修改时间预筛候选文件时采用保守策略，避免漏掉晚写入的旧事件。
7. 将文件排序规则绑定到分页候选快照。
8. 使用真实服务日志样本验证格式配置。

当前不建议假设所有服务日志时间格式统一，也不建议用文件修改时间替代日志行时间做精确过滤。
