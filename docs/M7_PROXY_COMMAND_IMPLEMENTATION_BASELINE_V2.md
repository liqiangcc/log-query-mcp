## 1. 当前实现范围

M7 已从设计阶段进入实际 Transport 实现阶段。

当前代码已经具备：

- v2 配置中的可选 `SshConnectionConfig.proxy`。
- `proxy.type=command`。
- `program + args[]` 直接进程启动模型，不构造 Shell command string。
- 仅允许完整 argv 项 `{host}` / `{port}` Placeholder。
- `SshStreamConnector` 将 Direct TCP 与 ProxyCommand 底层 stream 分离。
- Direct TCP 通过 `TcpStream` + `russh::client::connect_stream` 建立 SSH。
- ProxyCommand 通过 `tokio::process::Command` 启动管理员配置的本地 helper。
- child stdin 作为 SSH outbound stream，child stdout 作为 SSH inbound stream。
- ProxyCommand stream 继续进入现有 russh Handler、strict Host Key Verification、Authentication 和 SFTP 层。
- `kill_on_drop(true)` 作为 fail-closed child cleanup guard。
- ProxyCommand stream Drop 时调用 `start_kill()`，并在 Tokio runtime 可用时异步 `wait()` 回收 child。
- stderr 使用独立异步 drain；内存 capture 上限 64 KiB，达到上限后继续 drain 但不继续增长。
- 捕获的 stderr 当前不记录、不返回，避免在错误模型冻结前泄露潜在敏感信息。

## 2. 关注分离

实现继续保持：

```text
ProxyCommand = local byte-stream adapter
SSH          = protocol / authentication / host identity
SFTP         = remote read-only file access
Cache        = stable local snapshot
Query Engine = search
MCP          = AI-facing log API
```

`src/transport/proxy_command.rs` 只负责：

```text
validated config
      ↓
local child process
      ↓
stdin / stdout
      ↓
AsyncRead + AsyncWrite
```

它不负责：

```text
remote shell
remote command
remote path selection
log search
cache
sync
credential resolution
host-key policy
```

SSH 协议行为仍由 `src/transport/ssh.rs` 负责。

## 3. 安全边界

当前实现没有增加新的 MCP Tool，也没有向 MCP Client 暴露以下输入：

```text
proxy
program
args
host
port
```

ProxyCommand 只能来自管理员静态 v2 配置。

仍然不支持：

```text
ssh_exec
run_command
Shell command string
sh -c
bash -c
cmd /c generated by MCP
powershell -Command generated by MCP
credential placeholder
remote root/path placeholder
upload
write
delete
deploy
```

ProxyCommand 不获得 SSH password、private key、private-key passphrase 或 SecretResolver value。

Host Key Verification 仍使用逻辑目标 `connection.host` / `connection.port`，而不是 helper process 或宿主机身份。

## 4. Timeout / Lifecycle 当前语义

现有 `connect_timeout_millis` 继续作为 SSH 建连总 deadline，覆盖 connector 建立 stream 和 SSH handshake。

ProxyCommand child 被 stream 所有：

```text
ProxyCommandStream
├── ChildStdin
├── ChildStdout
├── Child
└── stderr drain task
```

stream Drop 时：

```text
abort stderr task
→ start_kill child
→ Tokio runtime 可用时 spawn wait/reap task
→ kill_on_drop 作为最终 guard
```

这已经比只依赖 Child Drop 更严格，但正式 RC 前仍需要 live fault tests 证明 timeout、cancellation、handshake failure、auth failure、SFTP failure 和 active-session crash 下没有可观察的 orphan process。

## 5. stderr 边界

stdout 是 SSH protocol stream，绝不进入日志系统。

stderr 当前：

- 使用 pipe 独立排空，避免 helper 因 stderr pipe 写满而阻塞。
- 最多在内存中保留 64 KiB。
- 超过上限后继续排空但不继续增长。
- 当前不写日志、不进入 Public Error、不返回 MCP Client。

后续只有在完成 redaction / diagnostic contract 后，才能考虑暴露稳定的内部 failure category；不能直接返回 raw stderr。

## 8. 下一阶段 M7-3 / M7-4

下一步重点不是继续扩展功能，而是完成生命周期与真实 Transport 证明：

1. 增加 ProxyCommand 专用 failure classification，避免所有启动/IO/early-exit 都折叠为普通 connect failure。
2. 增加 helper program not found / permission denied / early exit / stdout EOF / stderr flood / timeout / cancellation 测试。
3. 在真实 OpenSSH gate 中加入一个 stdio TCP proxy helper，证明 ProxyCommand SSH handshake、known_hosts、password/private-key auth、SFTP read 正常。
4. 验证 Direct 与 ProxyCommand 共用同一个 SSH semaphore。
5. 验证 Proxy server failure 不影响 Direct Remote / Local Source。
6. Billing 恢复后运行 Rust / Contracts / SSH Transport / Release gates。
7. 在真实 WSL + Windows Host 网络路径执行最终 acceptance。
