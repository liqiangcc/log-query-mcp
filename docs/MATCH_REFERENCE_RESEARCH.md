# R-07 安全 match_ref 与受控上下文读取预研

> 状态：自动化验证中  
> 实现：`src/match_reference.rs`、`src/context_reader.rs`

## 1. 目标

搜索接口只返回候选匹配行。AI 需要按需读取匹配位置前后的日志，但不能因此获得任意文件路径和任意行号读取能力。

R-07 验证以下链路：

```text
SafeRoot 安全打开文件
        ↓
有界扫描器产生 ScanMatch
        ↓
服务端创建不透明 match_ref
        ↓
客户端只持有 match_ref
        ↓
服务端解析引用并重新安全打开文件
        ↓
校验文件身份和匹配位置
        ↓
有界读取前后上下文
```

## 2. 引用模型

客户端可见引用格式：

```text
mref_<随机 UUID>
```

引用不可预测，不编码路径、日志来源、行号、inode 或关键字。

服务端内存保存：

```text
source_id
relative_path
file_identity { device, inode }
file_size_at_match
line_number
line_start_offset
match_byte_offset
keyword
case_sensitive
expires_at
```

内部引用数据不实现序列化，避免相对路径、inode 和偏移意外进入 MCP 响应。

## 3. 生命周期

`MatchReferenceStore` 提供：

- 固定容量。
- 固定 TTL。
- 插入时清理过期项。
- 达到容量时淘汰最旧引用。
- 服务重启后全部引用自然失效。
- 未知、格式错误和过期引用统一返回“未知或已过期”。

首期接受服务重启后引用失效，不为引用引入数据库或分布式缓存。

## 4. 引用创建约束

引用只能由服务端根据真实扫描结果创建。

`MatchReferenceData::from_scan_match` 将以下内容绑定：

- 管理员配置的日志来源标识。
- 来源根目录内的规范化相对路径。
- 安全打开文件得到的设备号和 inode。
- 扫描时文件大小。
- 扫描器返回的行号、行起点和匹配字节偏移。
- 原搜索关键字和大小写语义。

插入引用存储前再次校验：

- `source_id` 长度。
- 相对路径不能包含绝对路径、`.` 或 `..`。
- 关键字非空且不包含换行。
- 行号从 1 开始。
- 匹配偏移不能早于行起点。
- 匹配字节范围不能超过扫描时文件大小。

## 5. 文件重新验证

上下文读取不会复用客户端路径，也不会直接信任旧文件名。

服务端根据引用中的日志来源找到对应 `SafeRoot`，再通过 `openat2()` 重新打开相对路径，并校验：

1. 当前设备号和 inode 与扫描时一致。
2. 文件当前大小仍覆盖原匹配位置。
3. 行起点前一个字节仍为换行符，或行起点为文件开头。
4. 原关键字在原匹配字节偏移仍然存在。
5. 大小写比较规则与原搜索一致。

因此以下情况会使引用失效：

- 日志轮转后同名文件被替换。
- 文件被截断到匹配位置之前。
- 同一个 inode 的内容被原地改写，导致匹配内容变化。
- 相对路径不再能够安全打开。

## 6. 上下文读取边界

`read_referenced_context` 只接受：

- 服务端解析后的引用数据。
- `before_lines`。
- `after_lines`。
- 服务端定义的读取限制。

默认限制：

| 限制 | 默认值 | 硬上限 |
|---|---:|---:|
| 向后查找字节 | 4 MiB | 64 MiB |
| 向前读取字节 | 4 MiB | 64 MiB |
| 单行返回内容 | 16 KiB | 1 MiB |
| 返回内容合计 | 1 MiB | 16 MiB |
| 读取缓冲区 | 64 KiB | 1 MiB |
| 单侧上下文行数 | 请求值 | 50 |

向后查找采用分块逆向扫描换行符，不把匹配位置之前的全部文件内容加载到内存。

向前读取采用固定缓冲区，并对每条日志行设置返回长度上限。非法 UTF-8 使用有损文本返回并明确标记。

## 7. 已覆盖的自动化用例

- 生成两个不同且不可预测的引用。
- 引用不包含服务名或文件名。
- 正常解析引用元数据。
- 拒绝未知和被修改的 token。
- TTL 到期后引用失效。
- 达到容量后淘汰最旧引用。
- 新建 Store 模拟服务重启后旧引用失效。
- 拒绝包含 `..` 的内部路径和不一致字节偏移。
- 文件未变化时能够重新打开。
- 文件轮转并创建同名新文件后拒绝读取。
- 安全打开、扫描、存储、解析和读取上下文的完整链路。
- 同 inode 内容被改写后，通过关键字复核检测变化。
- 超大前置行触发有界回溯并明确标记。
- 超长上下文行被截断，不发生无界内存增长。
- 不合法上下文限制被拒绝。

## 8. 安全结论

当前方案不会向客户端开放：

- 文件路径。
- `file_id + line_number` 任意读取。
- 任意字节偏移。
- 完整文件下载。

`match_ref` 不是权限凭据，而是短期、不透明、服务端有状态的定位引用。真正的文件安全边界仍由日志来源白名单、`SafeRoot` 和 `openat2()` 提供。

- 不可预测 token。
- TTL 和容量限制。
- 文件身份绑定。
- 匹配位置复核。
- 有界前后文读取。
- 日志轮转和原地改写检测。

- 通过完整 MCP JSON 序列化限制最终响应大小。

首期建议单实例部署，并接受重启后引用失效。
