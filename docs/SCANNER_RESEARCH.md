# R-05 有界流式日志扫描器预研

> 状态：核心 POC 已通过自动化测试  
> 实现：`src/scanner.rs`

## 1. 目标

验证 Rust 能否在不把完整文件或完整日志行加载到内存的前提下，完成面向问题排查的普通字符串搜索，并强制执行扫描和返回限制。

本阶段重点验证：

- 跨读取缓冲区的字面量匹配。
- 中文 UTF-8 搜索。
- 大小写选项。
- 超长单行的有界处理。
- 非法 UTF-8 的稳定处理。
- 扫描字节、结果数量、单行预览和返回内容大小限制。
- 查询取消和截止时间的协作检查。

## 2. 实现方案

### 2.1 顺序流式读取

扫描器只依赖标准库 `Read` 接口：

```rust
pub fn scan_reader<R: Read>(
    reader: &mut R,
    request: &ScanRequest,
) -> Result<ScanOutcome, ScanError>
```

因此可以扫描：

- 普通 `File`。
- `SafeRoot` 安全打开后得到的文件。
- 测试用内存 Cursor。
- 后续可能增加的受限文件适配器。

扫描过程中只保留：

- 固定大小读取缓冲区。
- 当前行的有限匹配窗口。
- 已返回结果内容。

内存不会随单个日志文件大小线性增长。

### 2.2 字面量匹配

POC 使用流式 KMP 状态机匹配字节序列，支持关键字跨读取缓冲区边界，但不允许匹配跨越日志行边界。

搜索语义：

- 关键字必须非空。
- 关键字不能包含 `\n` 或 `\r`。
- 不解释为正则表达式、glob 或 Shell 表达式。
- 区分大小写时执行精确字节匹配。
- 不区分大小写时仅对 ASCII 字节执行大小写折叠。
- 非 ASCII 内容按 UTF-8 原始字节精确匹配。

采用 ASCII 大小写折叠是首期有意限制。它覆盖异常类名、错误码、请求标识和大部分英文日志，同时避免完整 Unicode case folding 带来的长度变化和匹配位置复杂度。

### 2.3 超长行处理

扫描器不会为完整日志行分配内存。

在首次发现匹配前，使用有限滚动窗口保存匹配位置前的字节；发现匹配后，再补充有限的后续字节。这样即使关键字位于超长行末尾，返回片段仍然包含关键字。

每条结果包含：

- 行号。
- 行首绝对字节偏移。
- 首次匹配绝对字节偏移。
- 有限日志片段。
- 原始行字节数。
- 内容是否截断。
- 内容是否经过 UTF-8 有损替换。

### 2.4 非法 UTF-8

搜索在字节层完成，因此文件中出现非法 UTF-8 不会导致扫描失败。

返回内容转换规则：

- 有效 UTF-8：原样返回。
- 非法 UTF-8：使用替换字符生成可返回文本。
- 设置 `content_lossy=true`，避免调用方误认为内容完全等同于原始字节。

### 2.5 资源限制

`ScanLimits` 当前支持：

| 限制 | 默认值 | POC 硬上限 |
|---|---:|---:|
| 最大扫描字节数 | 512 MiB | 由服务端配置决定 |
| 最大结果数 | 50 | 200 |
| 单条返回片段 | 16 KiB | 1 MiB |
| 返回内容合计 | 1 MiB | 16 MiB |
| 读取缓冲区 | 64 KiB | 1 MiB |

客户端后续只能在 MCP 层缩小限制，不能突破服务端硬限制。

`max_returned_content_bytes` 当前只计算日志内容字符串，不包含 JSON 字段名、元数据和协议封装。正式 MCP 响应仍需在上层增加完整序列化大小限制。

## 3. 停止原因

扫描结果使用以下内部停止原因：

```text
Complete
ResultLimit
ScanByteLimit
ReturnedContentByteLimit
Cancelled
DeadlineExceeded
```

这些值用于 POC 验证和内部控制，不要求全部暴露为复杂的 MCP 业务状态。

当扫描字节数正好达到上限时，扫描器不会额外读取一个字节来判断是否已经到达 EOF，因此会保守地返回 `ScanByteLimit`。

## 4. 已验证用例

自动化测试覆盖：

- 关键字跨读取缓冲区边界。
- 中文关键字。
- 默认 ASCII 大小写不敏感。
- 禁止跨行匹配。
- 超长行中较晚出现的关键字。
- 有限片段包含实际匹配内容。
- 非法 UTF-8。
- CRLF 展示时去除尾部 `\r`。
- 最大结果数。
- 最大扫描字节数。
- 最大返回内容大小。
- 查询预先取消。
- 截止时间已经到期。
- 空关键字、换行关键字和不合法限制。

## 5. 当前结论

R-05 核心技术结论为 **GO**：

- Rust 可以使用固定内存完成大文件顺序扫描。
- 不需要调用外部 `grep`、`rg` 或 Shell。
- 字面量搜索可以跨缓冲区工作。
- 超长行和非法编码不会导致无界分配或服务崩溃。
- 扫描和返回限制可以在业务层强制执行。
