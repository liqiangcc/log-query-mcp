# R-04 安全文件访问预研

> 状态：代码验证中  
> 目标平台：Linux kernel 5.6 及以上

## 1. 风险目标

日志查询 MCP 的主要文件安全风险是读取人工配置范围之外的文件，包括：

- `../` 路径穿越。
- 绝对路径。
- 最终文件为软链接。
- 中间目录为软链接。
- `/proc` 等文件系统中的 magic link。
- 校验后将普通文件替换成软链接。
- FIFO、Socket、设备文件等特殊文件。

仅依赖字符串前缀、一次性 `realpath` 或最终路径上的 `O_NOFOLLOW`，无法完整覆盖上述风险和检查后使用竞争条件。

## 2. 候选方案

### 2.1 固定日志根目录文件描述符

加载日志来源时，以不跟随最终软链接的方式打开管理员配置的根目录，并长期持有目录文件描述符。

后续文件访问全部从该文件描述符开始解析，而不是重新从任意绝对路径打开。

### 2.2 使用 `openat2()`

文件打开采用 Linux `openat2()`，当前 POC 使用：

```text
RESOLVE_BENEATH
RESOLVE_NO_SYMLINKS
RESOLVE_NO_MAGICLINKS
```

对应目标：

| 标志 | 作用 |
|---|---|
| `RESOLVE_BENEATH` | 路径解析不能逃离指定根目录 |
| `RESOLVE_NO_SYMLINKS` | 任意路径组件都不能经过软链接 |
| `RESOLVE_NO_MAGICLINKS` | 禁止 procfs 等 magic link |

文件打开标志包含：

```text
O_RDONLY
O_CLOEXEC
O_NOFOLLOW
O_NONBLOCK
```

`O_NONBLOCK` 主要用于避免误打开 FIFO 等对象时阻塞；打开后仍需检查对象类型。

### 2.3 打开后检查

文件打开成功后使用 `fstat`：

- 必须是普通文件。
- 记录设备号和 inode。
- 记录文件大小。

设备号和 inode 后续可用于 `match_ref` 上下文读取时确认文件身份，避免轮转后读取同名新文件。

### 2.4 规范化相对路径

应用层只接受内部文件发现器产生的相对路径，并拒绝：

- 空路径。
- 绝对路径。
- `.`。
- `..`。
- 非普通路径组件。

该检查用于尽早拒绝异常输入；真正的安全边界仍由 `openat2()` 的内核解析约束提供。

## 3. POC 类型

当前 POC 提供：

```rust
SafeRoot::open(configured_root)
SafeRoot::open_regular_file(relative_path)
```

返回的 `SafeFile` 包含：

```text
std::fs::File
FileIdentity { device, inode }
size
```

应用层启用：

```rust
#![forbid(unsafe_code)]
```

系统调用由 `rustix` 封装，POC 不自行编写 FFI 或裸指针代码。

## 4. 测试矩阵

当前单元测试覆盖：

- 正常打开和读取普通文件。
- 拒绝 `../outside.log`。
- 拒绝 `/etc/passwd`。
- 拒绝 `./application.log` 等未规范化路径。
- 拒绝最终文件软链接。
- 拒绝中间目录软链接。
- 拒绝日志根目录本身是软链接。
- 拒绝目录。
- 拒绝 FIFO。
- 拒绝 Unix Socket。
- 普通文件在打开前被替换为软链接时仍拒绝。

仍需补充或在独立集成环境验证：

- procfs magic link。
- 高并发文件替换和目录交换。
- 字符设备和块设备。
- 跨挂载点行为。
- 不同目标文件系统上的 `openat2()` 行为。
- 目标生产服务器内核版本盘点。

## 5. `RESOLVE_NO_XDEV` 决策

当前 POC 暂未启用 `RESOLVE_NO_XDEV`。

原因是合法日志目录可能包含独立挂载点；直接禁止跨挂载点可能影响部署方式。正式决策前需要确认：

- 日志目录是否可能是独立磁盘或 bind mount。
- 子目录是否允许包含其他挂载点。
- 是否应将每个挂载点配置为独立日志来源。

若业务不需要跨挂载点，正式实现建议启用该限制以进一步收窄边界。

## 6. 剩余风险和部署前提

### 6.1 硬链接

`RESOLVE_NO_SYMLINKS` 不等于禁止硬链接。如果具备日志目录写权限的用户能够把其他文件硬链接到日志目录，并且文件系统和权限允许，服务仍可能把它视为目录内普通文件。

因此需要：

- MCP 运行账号对日志目录只读。
- 非受信任用户不能在配置日志目录中创建文件或硬链接。
- 管理员只配置受控的日志目录。
- 根据部署模型评估是否需要校验所有者、文件系统或设备号。

### 6.2 旧内核

`openat2()` 需要 Linux 5.6 及以上。

旧内核不得静默退化成字符串前缀或一次性 `realpath` 方案。处理方式只能是：

1. 明确拒绝启动；或
2. 设计并单独评审等价安全的兼容实现。

### 6.3 文件发现

当前 POC只验证“已知相对路径的安全打开”，尚未实现目录遍历和文件名模式筛选。

后续文件发现器也必须：

- 从已打开的根目录描述符开始。
- 不跟随软链接。
- 只产生规范化相对路径。
- 对候选文件再次调用安全打开流程。

## 7. 与 MCP 工具的集成状态

当前 MCP 三个工具仍使用内存模拟数据。

`SafeRoot` 尚未接入 `search_logs`，这是有意的预研边界：先独立验证文件访问安全，再在 R-05 有界扫描器中集成。

## 8. 当前结论

基于目录文件描述符、`openat2()` 解析约束和打开后的普通文件校验，能够形成比路径字符串检查更可靠的文件访问边界。

R-04 只有在以下条件全部满足后才能判定通过：

- 格式、Clippy 和单元测试通过。
- 补充关键竞争条件和 magic link 测试。
- 确认目标 Linux 内核版本。
- 明确 `RESOLVE_NO_XDEV` 决策。
- 明确日志目录写权限和硬链接威胁模型。
