# M2 有界上下文读取

> 分支：`feat/context-reader`  
> 状态：实现中，等待严格 CI 收口

## 1. 目标

通过 `search_logs` 返回的短期 `match_ref` 读取匹配行前后的有限日志，同时不开放服务器路径、任意文件或任意行号读取。

```text
match_ref
  ↓
MatchReferenceStore
  ↓
source_id + 配置内相对路径 + 文件身份 + 匹配位置
  ↓
ConfiguredSource::open_configured_file
  ↓
有界前置窗口 + 匹配行 + 后置行
```

## 2. 安全复核

上下文读取前重新验证：

- 来源仍存在且启用。
- 相对路径仍属于来源配置范围。
- 文件仍通过 `openat2()` 和普通文件校验。
- device / inode 与搜索时一致。
- 当前文件大小不小于搜索快照和匹配结束位置。
- 保存的行起点仍是行边界。
- 原关键字仍位于保存的匹配字节偏移。

日志轮转、替换、截断或原地改写关键字都会使引用失效。

## 3. 资源边界

默认每个方向最多扫描 4 MiB，硬上限为 64 MiB。

同时限制：

- 单侧上下文行数。
- 单行预览字节数。
- 返回内容总字节数。
- 读取缓冲区。
- deadline 和 CancellationToken。
- 并发阻塞上下文任务。

## 4. 返回策略

内容预算优先级：

1. 匹配行。
2. 距离匹配最近的前置行。
3. 按顺序的后置行。

超长匹配行围绕关键字生成预览，保证关键字可见。非法 UTF-8 使用替换字符并明确标记。
