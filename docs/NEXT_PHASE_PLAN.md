# 正式实现阶段计划

> 前置结论：技术预研为 CONDITIONAL GO  
> 目标：将预研原型收敛为可评审、可部署、可验收的首期版本

---

## 1. 阶段原则

- 不继续在 spike 分支无限增加独立能力。
- 正式实现从 `main` 创建新分支。
- 预研代码按模块迁移并重新评审，不直接整体视为生产代码。
- 需求、MCP Schema、配置 Schema 和错误语义先冻结，再扩展功能。
- 首期范围优先保证安全、稳定和排查效果，不追求日志平台功能完整度。

---

## 2. 里程碑

### M1：范围与接口冻结

交付：

- 更新 `REQUIREMENTS.md`。
- 冻结三个 MCP 工具 Schema。
- 冻结 JSON 配置 Schema。
- 明确 `newest_first` 是否进入首期。
- 明确时间范围、ASCII 大小写和 token 失效语义。

退出标准：

- 需求和实际 POC 行为无冲突。
- 关键 ADR 已评审。

### M2：正式核心实现

交付：

- 正式 SourceRegistry。
- 安全文件发现和打开。
- 有界多文件搜索编排。
- match_ref 和上下文读取。
- 分页 cursor。
- 时间过滤与稳定排序。
- 统一错误映射和响应大小限制。

退出标准：

- 单元、集成、安全和协议测试全部通过。
- 生产代码无 `unsafe`。

### M3：部署与可观测性

交付：

- systemd 部署包。
- 配置检查和 doctor。
- 查询指标和结构化日志。
- CPU、内存、FD 和并发限制。
- 启停、升级和回滚说明。

退出标准：

- 非 root、只读日志权限下运行。
- 配置错误不会进入部分可用状态。

### M4：目标环境验收

交付：

- MCP Inspector 和实际 AI 客户端记录。
- 1 GiB、10 GiB 和 10,000 小文件基准。
- 1、4、8 并发数据。
- 日志追加、轮转、截断和删除压力测试。
- 客户端断连取消测试。
- systemd/cgroup 实测结果。

退出标准：

- 满足技术预研报告中的生产 GO 条件。

---

## 3. 建议任务拆分

### 接口与配置

- 定义版本化配置结构。
- 将所有资源硬上限配置化。
- 启动时输出生效配置摘要，不输出绝对日志路径。
- 对 source_id、文件列表和时间规则提供明确错误。

### 安全

- 保持 `openat2()` 为唯一文件打开路径。
- 增加 magic link、跨挂载点和并发替换集成测试。
- 完成 `RESOLVE_NO_XDEV` 决策。
- 增加依赖审计和许可证检查。

### 搜索

- 明确 `newest_first`：实现反向扫描，或从首期 Schema 移除。
- 对分页执行整个查询生命周期的累计资源限制。
- 记录排队耗时、扫描耗时和停止原因。
- 确保未知时间结果不伪造排序精度。

### MCP

- 固定 SDK 版本和协议版本测试。
- 验证至少一个实际 AI 客户端。
- 验证客户端断连和会话删除。
- 对工具错误保持稳定、简洁且不泄露系统信息。

### 运维

- 增加健康/就绪检查策略。
- 明确配置变更采用重启还是热加载。
- 编写升级与回滚步骤。
- 建立性能基准结果模板。
