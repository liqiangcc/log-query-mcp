# 受控日志上下文读取器预研

> 状态：POC 已实现，待严格 CI 和真实文件验证  
> 实现：`src/context_reader.rs`

## 1. 目标

`get_log_context` 需要根据服务端生成的 `match_ref` 返回匹配行前后的有限日志，而不能开放任意路径、任意文件或任意行号读取。

本 POC 串联：

```text
match_ref
  ↓
MatchReferenceStore
  ↓
source_id + 相对路径 + device/inode + 匹配位置
  ↓
SafeRoot::open_regular_file
  ↓
文件身份校验
  ↓
有界上下文读取
```

## 2. 输入边界

上下文读取器只接收服务端解析后的 `MatchReferenceData`，不接收客户端文件路径。

调用前必须完成：

- `match_ref` 存在且未过期。
- 引用属于已配置日志来源。
- 相对路径来自服务端状态。
- 文件通过 `openat2()` 安全重新打开。
- 设备号和 inode 与搜索时一致。

## 3. 资源限制

`ContextLimits` 控制：

- 单侧最大上下文行数。
- 单行最大返回字节数。
- 返回内容总字节数。
- 向前查找历史行的最大扫描字节数。
- 从匹配行向后的最大扫描字节数。
- 读取缓冲区大小。

POC 硬上限：

```text
每侧最多 50 行
单行最多 1 MiB
返回内容最多 16 MiB
单方向扫描最多 64 MiB
```

部署默认值更保守：

```text
单行 16 KiB
返回内容 1 MiB
向前扫描 4 MiB
向后扫描 4 MiB
读取缓冲区 64 KiB
```

## 4. 前置上下文

读取器根据保存的 `line_start_offset`，只读取匹配行之前的有限字节窗口：

1. 从窗口起点读取到匹配行起点。
2. 若窗口从某一行中间开始，丢弃该不完整行。
3. 保留距离匹配行最近的若干完整日志行。
4. 无法覆盖请求的全部前置行时设置 `before_truncated=true`。

这避免为获取少量前置上下文而从文件开头重新扫描整个日志。

## 5. 匹配行和后置上下文

读取器从保存的匹配行起始字节偏移继续读取：

- 校验目标位置确实位于行边界。
- 校验保存的匹配字节偏移仍落在该行内。
- 按单行预算读取匹配行和后续行。
- 向后扫描预算不足时，匹配行无法完整确认则拒绝返回。
- 后续行不足或响应预算不足时设置 `after_truncated=true`。

## 6. 返回结果

每行至少包含：

```text
line_number
content
content_truncated
content_lossy
original_line_bytes
is_match_line
```

非法 UTF-8 不会使服务崩溃；返回时使用替换字符，并设置 `content_lossy=true`。

## 7. 响应预算策略

匹配行优先级最高：

1. 必须保留匹配行。
2. 在剩余预算内从最近到最远加入前置行。
3. 再按顺序加入后置行。
4. 因预算无法返回的内容通过截断标记说明。

完整 MCP JSON 序列化大小仍需由更上层再次限制，因为当前统计只覆盖日志内容字符串。

## 8. 自动化测试

POC 测试覆盖：

- 返回匹配行前后指定数量的行。
- CRLF 行尾处理。
- 非法 UTF-8 有损标记。
- 超长日志行的有限预览。
- 行起始位置失效时拒绝读取。
- 匹配偏移已不在目标行时拒绝读取。
- 前置扫描窗口不足时标记截断。
- 响应预算较小时仍优先保留匹配行。
- 匹配行无法在向后扫描预算内完整读取时失败。

## 9. 已知限制

当前 POC 仍有以下限制：

- 对超长匹配行返回的是有限行预览，不保证关键字一定出现在预览片段中；正式实现应根据 `match_byte_offset` 生成围绕匹配位置的窗口。
- 文件内容在 inode 不变的情况下被原地覆盖，设备号和 inode 校验无法检测全部变化。
- 尚未保存匹配行摘要或内容哈希。
- 尚未接入 MCP `get_log_context` 工具。
- 尚未传播 MCP 请求取消和 deadline。
- 尚未验证持续追加和原地截断场景。

## 10. 当前结论

核心方向为 **CONDITIONAL GO**：

- 基于服务端引用和安全文件打开，可以避免任意文件读取接口。
- 前后上下文可以在固定字节、行数和响应预算内完成。
- 日志轮转和同名替换可通过文件身份校验拒绝。

在进入正式实现前，应优先补齐“围绕匹配位置的超长行预览”和“原地截断/覆盖检测”两项。
