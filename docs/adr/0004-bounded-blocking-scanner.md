# ADR-0004：使用有界同步扫描器和受限阻塞执行器

- 状态：Accepted
- 日期：2026-06-20

## 背景

普通日志文件读取是同步阻塞 I/O。直接在 Tokio 核心线程扫描大文件会阻塞 MCP 控制面；无限创建线程或任务会放大磁盘和内存压力。

## 决策

- 扫描器基于标准 `Read` 接口同步、流式读取。
- 扫描器使用固定缓冲区，不加载完整文件。
- 通过 `spawn_blocking` 与异步控制面隔离。
- 通过独立 Semaphore 限制同时运行的扫描任务。
- 扫描循环协作检查 CancellationToken、deadline 和资源配额。
- 不调用外部 `grep`、`rg` 或 Shell。

## 原因

- 文件 I/O 模型简单，便于测试超长行、非法编码和取消。
- `spawn_blocking` 隔离阻塞工作，但 Semaphore 才是项目级资源配额。
- 固定缓冲区让内存不随文件大小线性增长。
- 内部扫描器与 MCP 协议解耦，可复用在基准和集成测试中。

## 后果

正面：

- 控制面在大文件扫描期间仍可响应。
- 扫描字节、结果、单行和内容总量均可强制限制。
- 便于执行真实文件基准。

负面：

- 普通文件系统调用不能被安全强制中止，只能协作取消。
- 没有索引时查询成本与扫描数据量相关。
- `newest_first` 需要额外反向扫描或候选策略。

## 约束

- 每次扫描必须有绝对 deadline。
- 客户端参数只能缩小，不能扩大服务端硬限制。
- 正式上线前必须完成目标磁盘上的 1 GiB、10 GiB 和并发基准。
- systemd/cgroup 继续限制进程 CPU、内存和 FD。
