# ADR-0003：使用 openat2 建立文件访问边界

- 状态：Accepted
- 日期：2026-06-20

## 背景

日志 MCP 必须只读取管理员配置范围内的普通文件，并阻止路径穿越、软链接、magic link 和检查后替换攻击。

字符串前缀、一次性 `realpath` 和只在最终文件设置 `O_NOFOLLOW` 不能完整解决这些问题。

## 决策

在 Linux 上：

1. 启动时打开并持有每个日志来源根目录的文件描述符。
2. 文件路径始终相对于该根目录解析。
3. 使用 `openat2()` 和：

```text
RESOLVE_BENEATH
RESOLVE_NO_SYMLINKS
RESOLVE_NO_MAGICLINKS
```

4. 打开后使用 `fstat`，只接受普通文件。
5. 业务代码不执行 Shell，也不接受客户端路径。

## 原因

- 路径解析约束由内核在实际打开时执行。
- 可以避免检查与使用之间的常见竞态。
- 能阻止中间路径组件和最终文件的软链接。
- 设备号和 inode 可以用于轮转、引用和游标身份校验。

## 后果

正面：

- 文件边界清晰、可测试、可审计。
- 与 Rust `OwnedFd` 生命周期模型匹配。

负面：

- 要求 Linux kernel 5.6 及以上。
- 跨挂载点是否允许需要单独决定。
- 硬链接威胁仍依赖日志目录写权限控制。

## 约束

- 旧内核不得静默降级为字符串检查。
- MCP 运行账号对日志目录只读。
- 非可信用户不能在日志目录创建文件或硬链接。
- 部署前通过 doctor 检查内核和目录权限。
- `RESOLVE_NO_XDEV` 在目标部署拓扑确认后决定是否启用。
