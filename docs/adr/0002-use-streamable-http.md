# ADR-0002：远程服务使用 Streamable HTTP

- 状态：Accepted
- 日期：2026-06-20

## 背景

MCP 服务部署在能够访问日志文件的远程 Linux 服务器上，本地 AI 需要通过内网连接。stdio 适合本机子进程，但不适合跨主机部署。

## 决策

- 正式远程传输使用 Streamable HTTP。
- stdio 仅保留为本机调试和协议验证入口。
- 默认监听回环地址；监听内网地址必须显式配置。

## 原因

- 符合远程日志服务器部署模型。
- 支持标准 MCP 会话和结构化工具调用。
- 当前原型已验证协议协商、SSE、会话 ID、分页、上下文和会话删除。
- 与 systemd 和反向代理集成简单。

## 后果

正面：

- 客户端不需要在日志服务器本机启动子进程。
- 可以统一部署和升级。
- 便于日志、指标和连接管理。

负面：

- 需要处理 HTTP 会话、断连和请求取消。
- 首期没有内置认证和 TLS，依赖受控内网。
- 浏览器或跨域场景需要额外 Host/Origin 策略。

## 约束

- 不默认监听 `0.0.0.0`。
- 内网访问范围由防火墙、安全组或反向代理控制。
- 必须验证客户端断连到业务取消令牌的传递。
- 未来暴露到非受控网络时，必须重新设计认证、授权和 TLS。
